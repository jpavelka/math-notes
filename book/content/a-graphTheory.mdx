Familiarity with graph theory will be useful for this course. You don't need to know too much though, really just the basic definitions should be enough to understand the material. For interested readers, Reinhard Diestel's _Graph Theory_ <Cite id="diestel2018"/> is an excellent overview of the topic.

_Graph theory_ is a branch of mathematics that studies graphs. A _graph_ is composed of two sets $V$ and $E$ called the _vertices_ (also called _nodes_) and _edges_ (also called _arcs_), respectively. Graphs are used to model relationships (denoted by the edges) between pairs of entities (represented by the vertices). More concretely, let a graph $G=(V,E)$ be defined by the pair of sets $V$ and $E$. $V$ is the set of vertices, and the elements of $E$ are pairs of vertices $(v_1,v_2)$, with $v_1, v_2\in V$. Two vertices $v_1,v_2$ are said to be _neighbors_ if there is an edge between them, i.e. if $(v_1,v_2)\in E$. An alternative term is _adjacent_, i.e. vertices $v_1,v_2$ are neighbors if and only if they are adjacent.

<Definition id="def:graphTheory" title="Graph Theory">
The branch of mathematics that studies graphs.
</Definition>

<Definition id="def:graph" title="Graph">
A mathematical object $G=(V,E)$ consisting of a set of vertices $V$ and a set of edges $E$. Typically the vertices represent some object of interest, and the edges represent some pairwise relationship between two vertices.
</Definition>

<Definition id="def:vertex" title="Vertex">
Along with the edge, one of two main components of a graph. They're typically the base object of interest in a graph, and visually represented by a circle in a diagram.
</Definition>

<Definition id="def:node" title="Node">
See <Ref id="def:vertex"/>.
</Definition>

<Definition id="def:edge" title="Edge">
Along with the vertex, one of two main components of a graph. They typically represent relationships between vertices.
</Definition>

<Definition id="def:arc" title="Arc">
See <Ref id="def:edge"/>.
</Definition>

<Definition id="def:neighbor" title="Neighbor">
In a graph, a vertex $v_1\in V$ is a neighbor of another vertex $v_2\in V$ if an edge exists between the two, i.e. if $(v_1,v_2)\in E$.
</Definition>

<Definition id="def:adjacent" title="Adjacent">
In a graph, vertices $v_1\in V$ and $v_2\in V$ are adjacent if an edge exists between the two, i.e. if $(v_1,v_2)\in E$.
</Definition>

Initially, these definitions feel rather abstract. But in practice graphs often have very natural interpretations. Generally they are used to model relationships between entities, e.g. the nodes are people signed up for some social network, and an edge is drawn between two people if they are friends. Another common interpretation is as a road network, when the vertices are cities on a map, and an edge is drawn between two cities if it is possible to drive from one city to the other. In this case, there is often a distance $d_e$ associated with each $e\in E$ that denotes the distance between two cities, and you are perhaps trying to find the shortest route that lets you get from one place to another.

Sometimes it makes sense for the edges to be directional. For example, we might want to represent a road network with some one-way streets. Or perhaps we'd like to model teams from a sports league that have played each other, with the edges drawn "from" the winning team "to" the losing team. Such a graph with directed edges is called a _directed graph_, or _digraph_ for short. In these cases, the ordering of the vertices in each edge $(v_1,v_2)\in E$ matters, and we'd say that the edge goes _from_ $v_1$ _to_ $v_2$. <Ref id="fig:exampleDirectedGraph"/> shows an example visualization of a directed graph. Note that it is entirely possible for digraph edges to exist in both directions between a pair of vertices, as we see with both $(4,5)$ and $(5,4)$ existing in the figure.

<Definition id="def:directedGraph" title="Directed Graph">
A graph $G=(V,E)$ whose edges are directed, so that for two vertices $v_1, v_2\in V$ there is a difference between the edges $(v_1,v_2)$ (going from $v_1$ to $v_2$) and $(v_2,v_1)$ (going from $v_2$ to $v_1$).
</Definition>

In the context of digraphs, it is sometimes customary to denote the graph by $D=(V,A)$ instead of $G=(V,E)$, using $D$ (for digraph) in place of $G$ for the graph and $A$ (for arc) in place of $E$ for the edge set. Indeed, this is the convention Wolsey takes in <Cite id="wolsey2020"/>, but we will stick with $G=(V,E)$ for both graphs and digraphs in this course.

A graph $G=(V,E)$ is called _bipartite_ if its vertex set $V$ can be divided into two sets $V_1$ and $V_2$ such that every edge in $E$ connects a vertex in $V_1$ to a vertex in $V_2$. An example of such a graph is shown in <Ref id="fig:exampleBipartiteGraph"/>.

<Definition id="def:bipartite" title="Bipartite Graph">
A graph $G=(V,E)$ where the vertex set $V$ can be divided into two sets $V_1$ and $V_2$ such that every edge in $E$ connects a vertex in $V_1$ to a vertex in $V_2$ (as in <Ref id="fig:exampleBipartiteGraph"/>).
</Definition>

A general graph is said to be a _complete graph_ if every pair of vertices is connected by an edge. A complete graph with $n$ vertices is often denoted as $K_n$. A bipartite graph can also be called complete. A _complete bipartite graph_ is a bipartite graph with edges connecting each vertex in $V_1$ to each vertex in $V_2$. If a complete bipartite graph has $|V_1|=n$ and $|V_2|=m$, then we may denote the graph by $K_{n,m}$.

<Definition id="def:completeGraph" title="Complete Graph">
A graph in which every pair of vertices is connected by an edge.
</Definition>

<Definition id="def:completeBipartiteGraph" title="Complete Bipartite Graph">
A bipartite graph in which $(v_1,v_2)\in E$ for any $v_1\in V_1$, $v_2\in V_2$.
</Definition>

On a given graph $G$, a _walk_ is a sequence of edges which joins a sequence of vertices, such that it denotes a way to "walk" from vertex to vertex using the edges of the graph. So

$$
W=((1, 2), (2, 5), (4, 5), (2, 4), (2, 3))
$$

is a walk in the graph shown in <Ref id="fig:exampleGraph"/>, which represents traveling the sequence of vertices:

$$
1\rightarrow 2\rightarrow 5\rightarrow 4\rightarrow 2\rightarrow 3
$$

<Definition id="def:walk" title="Walk">
In graph theory, a sequence of edges which joins a sequence of vertices, such that it denotes a way to "walk" from vertex to vertex using the edges of the graph.
</Definition>

A very similar notion is that of a _trail_, which is a walk in which all the edges are distinct. Note that the walk $W$ from the previous paragraph is also a trail, since it does not repeat any edges. Meanwhile, a walk is called a _path_ if all its vertices (and therefore also its edges) are distinct. So $W$ is _not_ a path, since it travels to vertex $2$ twice. But something like

$$
P=((1, 2), (2, 5), (4, 5))
$$

_is_ a path, which we can visualize as in <Ref id="fig:examplePath"/>.

<Definition id="def:trail" title="Trail">
A walk in which all the edges are distinct.
</Definition>

<Definition id="def:path" title="Path">
A walk in which all the vertices are distinct.
</Definition>

A _circuit_ is a trail that starts and ends at the same vertex. Note that the circuit is defined based on a _trail_, so edges cannot be repeated in a circuit, though vertices _can_ repeat. A similar notion is the _cycle_, which is a path that begins and ends at the same vertex. A cycle is called a _Hamiltonian cycle_ if it visits every vertex exactly once. An example Hamiltonian cycle is shown in <Ref id="fig:exampleHamCycle"/>. Related to these is the _tour_, which is a walk that starts and ends at the same vertex and also visits every vertex _at least_ once (so a Hamiltonian cycle is also a tour, though not every tour is a Hamiltonian cycle).

<Definition id="def:circuit" title="Circuit">
A trail that starts and ends at the same vertex.
</Definition>

<Definition id="def:cycle" title="Cycle">
A path that begins and ends at the same vertex.
</Definition>

<Definition id="def:hamCycle" title="Hamiltonian Cycle">
A cycle in which every vertex is visited exactly once.
</Definition>

<Definition id="def:tour" title="Tour">
A walk that starts and ends at the same vertex and also visits every vertex at least once.
</Definition>

A graph is called _acyclic_ if it contains no cycles. Acyclic graphs are also sometimes called _forests_. A connected forest is called a _tree_. Given a graph $G=(V,E)$, a subset of $E$ is called a _spanning tree_ of $G$ if it creates a tree over all the vertices of $G$. An example spanning tree is shown in <Ref id="fig:exampleSpanningTree"/>.

The following is a neat fact about spanning trees that we use in the main text while talking about <Ref id="prob:mst"/>. It states that adding an edge to a spanning tree will create a cycle, and subsequently removing any edge from that cycle will give another spanning tree.

<Theorem id="thm:newSpanningTree">
Let $G=(V,E)$ be a graph and $T$ a spanning tree in $G$. Take any edge $e\in E$. Then:

1. $T\cup\{e\}$ contains a cycle $C$.
2. Let $e'$ be any edge in $C$. Then $T'=(T\cup\{e\})\setminus\{e'\}$ is a spanning tree.

</Theorem>
<Proof>
For claim 1, recall that a spanning tree is by definition connected, i.e. there is a path between any pair of vertices in the graph. Suppose the edge we add is $e=(u,v)$. Connectedness of $G$ implies there exists a path in $T$ starting at $u$ and ending at $v$. Then adding $e$ to that path gives you a new path starting and ending at $u$, i.e. a cycle.

Now for claim 2. Let $e'=(u',v')$ be the edge removed from $C$ to create $T'$. For $T'$ to still be a spanning tree, it must be acyclic (taken care of by the removal of $e'$) and it must still be connected, i.e. there must be a path between any pair of vertices in $T'$. So let $x,y\in V$ be two vertices. Since $T$ was a spanning tree, there was a path $P$ between $x$ and $y$ in $T$. If edge $e'$ is not part of that path, then $P$ is a subset of $T'$, i.e. it is still a path between $x$ and $y$ in $T'$. Otherwise, if $e'\in P$, the $x$-$y$ path in $T'$ looks like:

- Follow path $P$ from $x$ to $u'$
- Route from $u'$ to $v'$ the "other way" around $C$
- Follow path $P$ from $v'$ to $y$

Thus a path exists between any two vertices in $T'$.
</Proof>

<Definition id="def:matching" title="Matching">
A subset $M$ of the edges of a graph such that every vertex is included in at most one edge.
</Definition>

<Definition id="def:perfectMatching" title="Perfect Matching">
A matching in which every vertex is included in exactly one edge.
