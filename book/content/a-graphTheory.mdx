Familiarity with graph theory will be useful for this course. You don't need to be an expert, really just the basic definitions should be enough. For interested readers, Reinhard Diestel's _Graph Theory_ <Cite id="diestel2018"/> is an excellent overview of the topic.

## Basic definitions

<Definition id="def:graphTheory" title="Graph Theory">
The branch of mathematics that studies graphs.
</Definition>

<Definition id="def:graph" title="Graph">
A mathematical object $G=(V,E)$ consisting of a set of vertices $V$ and a set of edges $E$. Typically the vertices represent some object of interest, and the edges represent some pairwise relationship between two vertices.
</Definition>

<Definition id="def:vertex" title="Vertex" alt="Node">
One of two main components of a graph (along with the edge). The vertex is typically the base object of interest in a graph. In graph visuals, vertices are usually represented by a circle.
</Definition>

<Definition id="def:edge" title="Edge">
One of two main components of a graph (along with the vertex). Each edge $e\in E$ is given by a pair of vertices $v_1,v_2\in V$, i.e. $e=(v_1, v_2)$. Edges typically represent relationships between vertices. In graph visuals, they are usually drawn as a line connecting two vertices.
</Definition>

<Definition id="def:neighbor" title="Neighbor">
In a graph, a vertex $v_1\in V$ is a **neighbor** of another vertex $v_2\in V$ if an edge exists between the two, i.e. if $(v_1,v_2)\in E$.
</Definition>

<Definition id="def:adjacent" title="Adjacent">
In a graph, vertices $v_1\in V$ and $v_2\in V$ are said to be **adjacent** if an edge exists between the two, i.e. if $(v_1,v_2)\in E$.
</Definition>

Initially, these definitions feel rather abstract. But in practice graphs often have very natural interpretations. Generally they are used to model relationships between entities, e.g. the nodes are people signed up for some social network, and an edge is drawn between two people if they are friends. Another common interpretation is as a road network, when the vertices are cities on a map, and an edge is drawn between two cities if it is possible to drive from one city to the other. In this case, there is often a distance $d_e$ associated with each $e\in E$ that denotes the distance between two cities, and you are perhaps trying to find the shortest route that lets you get from one place to another.

Graphs are typically represented visually as in <Ref id="fig:exampleGraph"/>: Each vertex is represented as a circle in the diagram, while edges are denoted by lines between the circles. In the case of <Ref id="fig:exampleGraph"/>, the graph being represented is a graph $G=(V,E)$ with vertices:

$$
V=\{1,2,3,4,5\}
$$

and edges:

$$
E=\{(1,2), (1,3), (2,3), (2,4), (2,5), (3,5), (4,5)\}
$$

Sometimes it makes sense for the edges to be directional. For example, we might want to represent a road network with some one-way streets. Or perhaps we'd like to model teams from a sports league that have played each other, with the edges drawn "from" the winning team "to" the losing team. Such a graph with directed edges is called a _directed graph_, or _digraph_ for short.

<Definition id="def:directedGraph" title="Directed Graph" alt="Digraph">
A graph $G=(V,E)$ whose edges are directed, so that for two vertices $v_1, v_2\in V$ there is a difference between the edges $(v_1,v_2)$ (going from $v_1$ to $v_2$) and $(v_2,v_1)$ (going from $v_2$ to $v_1$).
</Definition>

In these cases, the ordering of the vertices in each edge $(v_1,v_2)\in E$ matters, and we'd say that the edge goes _from_ $v_1$ _to_ $v_2$. <Ref id="fig:exampleDirectedGraph"/> shows an example visualization of a directed graph. Note that it is entirely possible for digraph edges to exist in both directions between a pair of vertices, as we see with both $(4,5)$ and $(5,4)$ existing in the figure.

In the context of digraphs, it is sometimes customary to denote the graph by $D=(V,A)$ instead of $G=(V,E)$, using $D$ (for digraph) in place of $G$ for the graph and $A$ (for arc) in place of $E$ for the edge set. Indeed, this is the convention Wolsey takes in <Cite id="wolsey2020"/>, but we will stick with $G=(V,E)$ for both graphs and digraphs in this course.

## Structures within graphs

Many combinatorial optimization problems start with some graph and ask you to find certain types of structures within the graph. Here are some important graph structures:

<Definition id="def:walk" title="Walk">
  A sequence of edges which joins a sequence of vertices in a graph, such that it denotes a way to "walk" from vertex to vertex using the edges of the graph.
</Definition>

For example,

$$ {#eq:exampleWalk}
  W=((1, 2), (2, 5), (4, 5), (2, 4), (2, 3))
$$

is a walk in the graph shown in <Ref id="fig:exampleGraph"/>, which represents traveling the sequence of vertices:

$$
1\rightarrow 2\rightarrow 5\rightarrow 4\rightarrow 2\rightarrow 3
$$

A couple very similar notions:

<Definition id="def:trail" title="Trail">
  A <Ref id="def:walk" useTitle={true} textTransform="lowercase"/> in which all the edges are distinct.
</Definition>

<Definition id="def:path" title="Path">
  A <Ref id="def:walk" useTitle={true} textTransform="lowercase"/> in which all the vertices are distinct.
</Definition>

So <Ref id="eq:exampleWalk"/> describes a _trail_ in the graph from <Ref id="fig:exampleGraph"/>, but not a _path_. But something like $
P=((1, 2), (2, 5), (4, 5))$ (depicted in <Ref id="fig:examplePath"/>) _is_ a path, since no vertex is visited twice.

The next group if definitions concern graph structures that are "circular" in some manner:

<Definition id="def:circuit" title="Circuit">
  A <Ref id="def:trail" useTitle={true} textTransform="lowercase"/> that starts and ends at the same vertex.
</Definition>

<Definition id="def:cycle" title="Cycle">
  A <Ref id="def:path" useTitle={true} textTransform="lowercase"/> that begins and ends at the same vertex.
</Definition>

<Definition id="def:hamCycle" title="Hamiltonian Cycle">
  A <Ref id="def:cycle" useTitle={true} textTransform="lowercase"/> in which every vertex is visited exactly once.
</Definition>

<Definition id="def:tour" title="Tour">
  A <Ref id="def:walk" useTitle={true} textTransform="lowercase"/> that starts and ends at the same vertex and also visits every vertex at least once.
</Definition>

Note that the circuit is defined based on a _trail_, so edges cannot be repeated in a circuit, though vertices _can_ repeat. The _cycle_ is based on a path, so vertices _cannot_ repeat. Every Hamiltonian cycle is also a tour, though not every tour is a Hamiltonian cycle (since tours can repeat vertices).

The following is a neat fact about spanning trees that we use in the main text while talking about <Ref id="prob:mst"/>. It states that adding an edge to a spanning tree will create a cycle, and subsequently removing any edge from that cycle will give another spanning tree.

<Theorem id="thm:newSpanningTree">
Let $G=(V,E)$ be a graph and $T$ a spanning tree in $G$. Take any edge $e\in E$. Then:

1. $T\cup\{e\}$ contains a cycle $C$.
2. Let $e'$ be any edge in $C$. Then $T'=(T\cup\{e\})\setminus\{e'\}$ is a spanning tree.

</Theorem>
<Proof>
For claim 1, recall that a spanning tree is by definition connected, i.e. there is a path between any pair of vertices in the graph. Suppose the edge we add is $e=(u,v)$. Connectedness of $G$ implies there exists a path in $T$ starting at $u$ and ending at $v$. Then adding $e$ to that path gives you a new path starting and ending at $u$, i.e. a cycle.

Now for claim 2. Let $e'=(u',v')$ be the edge removed from $C$ to create $T'$. For $T'$ to still be a spanning tree, it must be acyclic (taken care of by the removal of $e'$) and it must still be connected, i.e. there must be a path between any pair of vertices in $T'$. So let $x,y\in V$ be two vertices. Since $T$ was a spanning tree, there was a path $P$ between $x$ and $y$ in $T$. If edge $e'$ is not part of that path, then $P$ is a subset of $T'$, i.e. it is still a path between $x$ and $y$ in $T'$. Otherwise, if $e'\in P$, the $x$-$y$ path in $T'$ looks like:

- Follow path $P$ from $x$ to $u'$
- Route from $u'$ to $v'$ the "other way" around $C$
- Follow path $P$ from $v'$ to $y$

Thus a path exists between any two vertices in $T'$.
</Proof>
